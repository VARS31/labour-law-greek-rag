# Enhancer report: rewriting the question before searching (Phase 3B)

Phase 3B adds the Query Enhancer: one model call that turns a person's question into searches in the words of the law. Retrieval only, on the dev questions, so no answers were written. It also makes qwen3 the default and fixes the repeat filter, because both change what the enhancer is measured against. This file is generated by [`scripts/enhancer_report.py`](../scripts/enhancer_report.py) from the stored runs in [`eval/results/`](../eval/results/). Don't edit it by hand.

## The result

**The enhancer doesn't bring more right chunks to the writer.** Without it, the right chunk arrives for 22 of 27 dev questions. The model's phrasings alone bring 21. The phrasings together with the person's own question bring 22: the very same questions as without the enhancer. It costs a median of 7.2 s per question, so as a first step on every question it doesn't pay for itself.

**Why.** First, semantic search with qwen3 had already solved most of what the enhancer was for. Three of the 4 vocabulary questions arrive without it, at rank 1 or 2. In Phase 2, with bge-m3 and RRF, none did. Second, this model doesn't know the law's words. For `vocab-01` it writes "οικοδομικές εργασίες" every time and never "εργοτάξια", which is the word it would need. Its katharevousa is often not real Greek: "μισθώδεια", "μεροκαιρομισθούντων", "υπερπερισσότερον".

**It isn't useless.** It reaches different chunks. Through the phrasings alone `sector-05` arrives, which plain search misses, and `sector-01` moves from rank 6 to 2. But others move down, and on these questions the two cancel out.

**What I'd do with it.** Not run it first. In the agent, search with the plain question first, and use the enhancer for the second try, when the judge says the chunks don't answer. Then the 7 seconds are spent only when they're needed, and the second try searches differently from the first. That is untested, because the judge doesn't exist yet.

## How the enhancer works

One call to `ministral-3:8b` at temperature 0, with its instructions in [`prompts/enhancer.md`](../prompts/enhancer.md). It returns JSON with `rewritten`, `variants`, `law_refs` and `topic_hint`. Asked again with 5 of the questions, it gave the same answer word for word.

**The code checks the answer,** because a JSON schema fixes only its shape. All 32 of 32 answers could be read. A law or article in `law_refs` must be written in the question: 0 were dropped, and it found the law in all 4 questions that name one (`lookup-01`, `lookup-03`, `refuse-01`, `refuse-04`). A search phrase with a number the question doesn't contain is dropped too: 3 phrases, in 2 questions. I added that check after seeing the results.

**Combining the searches.** Each chunk keeps its highest similarity to any one search, and chunks are ranked by that, so being found by several searches earns nothing. That reward is what buried the right chunks under RRF. Then come repeat removal and the limit, keeping 8. If `law_refs` isn't empty, keyword search for those laws may add up to 2 chunks after the first 6, like variant (e) in Phase 3A.

**Two ways of searching.** The brief was to search each phrasing, so that's measured. I also measured the phrasings together with the person's own question, because the phrasings can drift away from what plain search already finds, and they do: top 50 falls from 27 to 25 without it. `enhancer.ranked` takes the question as an option, and the agent should pass it.

**The prompt's examples are on other topics.** [`scripts/check_enhancer_prompt.py`](../scripts/check_enhancer_prompt.py) checks them against all 52 items of `eval/questions.jsonl`, and `tests/test_enhancer.py` runs the same check. A topic word or law number may appear nowhere in a question, key fact, gold quote or note, and an example question may share at most 40% of its words with a test question. **Result: no problems.**

## Housekeeping

### qwen3 is the default

Search, `labour_rag.ask` and `labour_rag.evaluate` now use `qwen3-embedding:4b` with its query instruction, on the project owner's decision after Phase 3A. `--embedding bge-m3` selects the old model, and its vectors stay in the `chunks` table. The scripts behind the Phase 1B and 1C reports stay on bge-m3, so those reports still describe what they measured. A new setup now also needs the model and about 2.5 hours of embedding.

### The repeat filter

Two chunks with different numbers are no longer repeats, and among real repeats the newest act is kept. So on bge-m3 the writer now gets Π.Δ. 176/1997's 16 weeks instead of losing it to a 15-week decision from 1989, and on qwen3 `single-32` gets the 1986 decision where it used to get the 1985 one with the same text.

**One choice the project owner should check: which numbers count.** The brief says different numbers in the text. I count numbers with a unit (`16 εβδομάδες`, `10%`, `27.012 δρχ`, `πέντε ημέρες`), not every digit. Read literally, the rule almost switches the filter off, because many digits in a chunk only name something: `Αριθ. 103100/4990 της 10/12 Δεκ. 1970 (ΦΕΚ Β΄897)`. The same bonus decision re-issued the next year differs in all of those. `--number-rule digits` selects the literal reading, and both are measured here:

| Repeat rule | Right chunk, qwen3 | Removed as repeats, qwen3 | Near-identical pairs reaching the writer, qwen3 | Right chunk, bge-m3 |
|---|---:|---:|---:|---:|
| Old filter | 22 | 41 | 0, in 0 questions | 17 |
| Numbers with a unit (new default) | 22 | 45 | 8, in 5 questions | 18 |
| Every digit (literal) | 22 | 6 | 28, in 9 questions | 18 |

The old filter was removing real differences: of the 26 pairs it treated as repeats on these questions, 23 differ in some digit and 14 in a number with a unit (counted once on both models, with no limit applied, and not stored). The new default keeps those 14 apart. Its removed count is higher only because the walk now reads all 30 results to find newer repeats.

Both new rules bring back the same question, so the literal reading buys nothing here, and it costs a lot. On `single-21` it hands the writer 9 near-identical pairs, and on `vocab-02` 6, all stating the same numbers with units: bonus decisions from different years repeating one rule. The new default hands over none on either. The 8 pairs it does let through are chunks that really do state different numbers, which is what the rule wants. On `vocab-02` it delivers only 6 chunks, because repeats and the limit use up the first 30 results.

## What this doesn't show

- **No answers were written.** These numbers say which chunks reach the writer, not whether its answers are better.
- **Only 27 questions, and I've now read all of them.** One question is about 4 points. I wrote the examples and the checks after looking at these same questions, so a real test needs new ones. The test split wasn't touched.
- **One small model.** All of this is `ministral-3:8b`. A stronger model might know the law's words better. Phase 4 can test that.
- **Refusals weren't measured.** Questions that must be refused have no gold chunk, so they don't count in any number above.
- **The writer now sees old and new rules side by side.** On `single-15` it gets 14, 15 and 16 weeks. The filter is right to keep them, but picking the newest is now someone's job, and the judge is the place for it.
